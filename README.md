# منصة الاختبار اللحظي — اختبار الاقترانات (الوحدة الثانية، الدروس ١–٦)

> React 19 · TypeScript · Vite · Supabase Realtime · RLS
> لوحة معلّم + صفحة طلاب لحظية supporting ١٠٠–٢٠٠ طالباً.

تحويل صفحة الاختبار الأصلية (ملف HTML واحد) إلى **منصّة اختبار حيّة** كاملة:
صفحة إدارة للمعلّم، صفحة طلاب خفيفة جداً، ولعبة لحظية تُدار من Supabase Realtime.

التصميم والأنيميشن **مطابقان للتصميم الأصلي** (الوضع الأبيض افتراضياً، نفس
الإطارات والظلال والانيميشن). الاختلاف الوحيد المقصود هو **مكان الإجابات**:
أثناء الجولة لا يُرسَل الإجابة الصحيحة إلى المتصفح إطلاقاً.

> 🔒 اقرأ [SECURITY.md](SECURITY.md) قبل النشر. لا مفاتيح سرّية في هذا المستودع.
> 📖 [دليل النشر والنشر على Vercel](DEPLOY.md).

> **الأسئلة مولَّدة آلياً من الملف الأصلي** ولا تُحرَّر يدوياً:
> `npm run verify:port` يقارن ٣٧٢ عنصراً (نصوص + كل `path` و`circle` و`line`
> و`text`) حرفاً بحرف مع `__اختبار الاقترانات…html`.

### ب. تطبيق قاعدة البيانات

1. افتح مشروعك في [supabase.com/dashboard](https://supabase.com/dashboard)
2. **SQL Editor → New query**
3. انسخ محتوى `supabase/schema.sql` كاملاً والصقه ثم **Run**

> الملف **آمن لإعادة التشغيل**: كل الجمل إما `create … if not exists` أو
> `create or replace` أو داخل `exception` handler، فإعادة تشغيله على قاعدة
> جزئية لا تُنتج أخطاء.

الملف مُتحقَّق منه بمحرك PostgreSQL الحقيقي:

```bash
npm run check:sql
# ✔ toplevel : 64 statements parsed          ← بناء الجملة (DDL + PL/pgSQL)
# ✔ plpgsql  : 28 bodies analysed            ← صياغة أجسام الدوال
# ✔ declaration order ok — 8 tables, 23 functions, 68 statements
```

> **ترتيب التصريح مهم:** PostgreSQL يتحقّق من جمل SQL داخل جسم دالة PL/pgSQL
> لحظة إنشاء الدالة. لذلك كل الجداول تُنشأ **قبل** الدوال التي تقرأها.
> الفحص الثالث أعلاه يحرس هذا الترتيب آلياً.

> **لا اعتماد على pgcrypto:** الدوال تثبّت `search_path = public, pg_temp`،
> بينما Supabase يثبّت `pgcrypto` في مخطّط `extensions`. لذلك توليد الكود
> يستعمل `md5()` و `random()` و `gen_random_uuid()` المدمجة فقط.

المهمّة التالية للمعلّم (اختيارية لكن مُوصى بها) — التنظيف الدوري:

```sql
-- Database → Cron → Add job  (كل ١٠ دقائق)
select cron.schedule('quiz-sweep', '0,10,20,30,40,50 * * * *',
                     $$ select public.maintenance_sweep(); $$);
```

## ٣) كيف تعمل اللعبة

### الطالب

| الخطوة | الشاشة |
|---|---|
| ١ | `#/join` — إدخال الكود (أو رابط `#/j/ABC-DEF` مباشرة) |
| ٢ | **اختر ايموجي** — دائرة كبيرة، **الضغط عليها يبدّل البانر**، وتحتها حقل الاسم |
| ٣ | **غرفة الانتظار** — كل الطلاب بأيقوناتهم وأسمائهم + ترتيب مبدئي |
| ٤ | **السؤال** — عدّاد تنازلي من وقت المعلّم (٢٠ ثانية افتراضياً) |
| ٥ | بعد الإجابة: «تم تسجيل إجابتك» + شريط «مَن أجاب؟» |
| ٦ | **الكشف** — الصحيح/الخطأ، النقاط، الحل، والترتيب الحالي |
| ٧ | **النتائج النهائية** — منصة التتويج، خريطة الأسئلة، لوحة الترتيب |

### المعلّم

- **كود دخول يتجدّد كل ٢٤ ساعة** (يمكن تدويره يدوياً فوراً) + زر نسخ الرابط.
- **فتح/إغلاق الباب** لاستقبال الطلاب في أي لحظة.
- **ابدأ اللعبة / السؤال التالي / كشف الحل الآن / +ثانية / إيقاف مؤقت / إنهاء**.
- **شاشة الطلاب** — محاكاة حيّة تُفتح تلقائياً عند بدء أي سؤال، فترى ما يراه
  الطلاب بالضبط: السؤال، الخيارات، والعدّاد التنازلي الحقيقي. وعندما ينتهي
  السؤال يظهر **نص الحل تحت السؤال مباشرة** لتقرأه للطلاب بصوت مسموع.
  الخيارات فيها **معطّلة تماماً** — المعلّم يراقب ولا يُسجَّل له أي إجابة.
- **ترتيب الطلاب كاملاً**: الأول فالثاني فالثالث … حتى **آخر طالب في الصف**، بنفس
  نمط المنصة الأولى الثلاثة، داخل صندوق يتمرّر داخلياً — فلا يدفع باقي اللوحة
  خارج الشاشة حتى مع ٢٠٠ طالب.
- **مراقبة حيّة**: شبكة طلاب (من أجاب، من ما زال يفكّر، slowest) + توزيع
  الإجابات + لوحة النتائج على الجنب + عداد `أجابوا x من y`.
- **بنك الأسئلة**: إضافة/تعديل/حذف/ترتيب/تفعيل، ومعاينة حية للرسم البياني.
- **التقرير النهائي**: ترتيب كامل، تحليل كل سؤال (نسبة الإجابة + توزيع
  الخيارات)، وتصدير CSV.

> **شاشة الطلاب** لا تحتاج صلاحية إضافية ولا دالة جديدة في القاعدة: تقرأ نفس
> حمولة `rpc_sync` التي يقرأها الطالب، فالسؤال لا يحمل `correct_index` أصلاً
> ولا يصل نص الحل إلا بعد انتهاء الوقت. لا يرى المعلّم فيها أكثر مما يراه
> الطالب — الفرق الوحيد أن الخيارات معطّلة.

## ٤) نظام النقاط

```
إجابة صحيحة  →  500 + 500 × (الوقت المتبقي ÷ مدة السؤال)   ⇒  من ٥٠٠ إلى ١٠٠٠
إجابة خاطئة  →  ٠
لم يجب       →  ٠  (+ تُسجَّل كـ«راحت عليك»)
```

**زمن الإجابة يقيسه الخادم** (`now() − question_started_at`) ولا يثق بما يرسله
المتصفح إطلاقاً، فلا يمكن تزوير مكافأة السرعة.

## ٥) الأمان — لماذا الإجابة الصحيحة لا تتسرب

| التهديد | الحماية |
|---|---|
| طالب يقلب الإجابة الصحيحة من المتصفح | الإجابة الصحيحة **لا تغادر قاعدة البيانات** أثناء الجولة؛ `get_question()` لا يُرجع `correct_index` أبداً |
| طالب يطلب الحل مبكراً | `rpc_settle()` يرفض قبل انتهاء الوقت (ولا يقبل إلا المعلّم قسراً) |
| طالب يسرّع عدّاده | الزمن يُحسب في `rpc_answer` على الخادم |
| طالب يكتب باسم طالب آخر | كل نداء يمرّ بـ `client_key` الخاص بالجهاز ويُتحقَّق منه |
| طالب يغشّر بمعرّفات مزوّرة | `answers` عليه `unique(session_id, player_id, slot)` وأول إجابة فقط تُحتسب |
| طالب يرى نتائج الآخرين مباشرة | `results` و`player_stats` **بلا سياسة قراءة عامة**؛ تصل إليه عبر حمولة الكشف فقط |
| أحد يفتح الجداول مباشرة | RLS مفعّل على كل الجداول، والكتابة للمعلّم المسجّل فقط عبر `assert_teacher()` |
| مفتاح سري في المتصفح | المتصفح لا يحمل سوى `VITE_SUPABASE_ANON_KEY` (Publishable). المفتاح الإداري في `.env.local` ويُقرأ فقط في سكربتات Node |

> 🔑 **أي مفاتيح تكتبها في المستودع العمومي تُعتبر مكشوفة.**
> ضع المفاتيح في **Environment Variables** داخل Vercel (أو في `.env.local`
> على جهازك فقط). للاستخدام الشخصي: **Settings → API Keys** ثم دوّر المفتاح.

## ٦) الأداء — ليعمل ١٠٠–٢٠٠ طالب

- **صفحة الطالب حزمة واحدة صغيرة**: حزمة `admin` (٥٧ ك.ب) وحزمة `bank`
  (١٤ ك.ب) لا تُحمَّلان إلا عند فتح لوحة المعلّم.
- **لا استطلاع (polling)**: WebSocket واحد لكل جهاز + نبضة واحدة كل ١٨ ثانية
  تُعيد الحالة-authoritative + مزامنة الساعة + كشف الحالة.
- **العدّاد على ساعة الخادم**: كل جهاز يحسب `question_ends_at` بعد تصحيح
  انحراف الساعة عبر RTT، فالعدّاد متطابق على كل الشاشات.
- **فهارس** على `(session_id, slot)` و`(session_id, last_seen)` و
  `(session_id, total_points)`.
- **الرسوم البيانية** تُرسم مرة واحدة وتُخزَّن في `jsonb` — لا حساب على الجهاز.
- `eventsPerSecond: 12` كحد أعلى للأحداث لكل مشترك.

### ★-bank مطابقة الأصل

بنك الأسئلة **مولَّد آلياً** من الملف الأصلي — لا كتابة يدوية:

1. `scripts/generate-bank.mjs` ينفّذ محرّك الملف الأصلي داخل بيئة معزولة.
2. يعترض الدالة `G()` لفحص المواصفات الحقيقية لكل رسم.
3. **يستنتج** معادلة كل منحنى بالعيّنة (`√(x−h)+k` · `|x−h|+k` · كثير حدود لدرجة ٣).
4. يعيد بناء `src/data/questionBank.ts`.
5. `scripts/verify-port.mjs` يعيد تصيير الطرفين ويقارن:
   `viewBox` + كل `path d` + كل `circle` + كل `line` + كل `text`.

> **اكتُشفت并进行 إصلاحها أخطاء حقيقية عبر هذا المِقياس:**
> `sq` في الأصل هو `Math.sqrt` (جذر) لا مربّع — كانت المنحنيات الأربعة في السؤال الخامس
> خاطئة تماماً. كذلك: خط الأعداد يرسم `n+1` إشارة لا `n`، وكل منحنيات الأصل تحمل
> `class="cv"`، وعلامات `<` `>` في النصوص تبقى حرفية كما في الأصل.

للتحقق من أي تعديل مستقبلي على بنك الأسئلة:

```bash
npm run generate:bank && npm run verify:port && npm run seed && npm run verify:db
```

## ٩) نصوص الأسئلة

يكتب النص ببساطة، وكل ما بين `{}` يصير رقماً رياضياً بخط موحّد:

```
ما مجموعة حل المتباينة {س^2 + 3س < 4}؟
```

| الرمز | النتيجة |
|---|---|
| `{ … }` | شريحة رياضية بخط monospace واتجاه LTR |
| `س^2` | أُس |
| `√(س+2)` أو `√س` | جذر بخطّ علوي |
| `‹-8\|2›` | كسر مكدّس |
| `-` | يتحوّل تلقائياً إلى `−` (U+2212) |
| الأرقام | تُعرض ٠١٢٣٤٥٦٧٨٩ تلقائياً |

الرسوم البيانية تُخزَّن كـ JSON إجرائي:

```jsonc
{ "x": [-4, 6], "y": [-4, 7], "width": 330,
  "curves": [
    { "kind": "poly", "c": [0, 0, 1],     "color": "#2b59ff" },   // س²
    { "kind": "poly", "c": [1, -4, 1],    "color": "#d6336c" },   // (س−٢)²−٣
    { "kind": "abs",  "h": 2, "k": 1,     "color": "#d6336c" },   // |س−٢|+١
    { "kind": "sqrt", "domain": [0, 6], "dash": true }
  ],
  "points": [{ "x": 2, "y": -3, "color": "#d6336c" }],
  "hlines": [{ "y": 275, "color": "#d6336c" }],
  "texts":  [{ "x": 4.4, "y": 3.8, "text": "ل", "color": "#d6336c" }]
}
```

`c` هو معاملات كثير الحدود بالترتيب `[ثابت، س، س²، س³]`.
